# WhereQ Universe v1.1.0 — Cloud + CC join the galaxy

> **Six timeless questions. Ten living products. One universe — bigger than ever.**

Two new planets join the WhereQ Universe today, and the architecture
grows a layer most ecosystems never get right: **a shared data backbone**.

## What's in this release

- **WhereQ Cloud** — the data platform. The shared PostgreSQL schema
  and every scheduled collection job now live in one place. Free-tier
  providers stream market data, feeds and metrics into a single
  source of truth that FlowDesk (and the rest of the outer orbit)
  reads from.
- **WhereQ.cc** — the private gallery. Graduated from incubation.
  A strictly-local photo vault: your originals live encrypted in
  your own browser and never leave it, while on-demand AI can
  enhance, describe and animate a single image whenever you ask.
- **Architecture docs** — the new `§19. Release & Deploy Runbook`
  in `docs/ARCHITECTURE.md` codifies the pre-deploy checklist,
  the four npm scripts, the COOP/COEP smoke test, the Vercel
  auto-deploy flow, the rollback procedure, and a trouble-shooting
  table.

## The architecture that's emerging

With this release the universe diagram finally matches the way the
products actually depend on each other in code:

- The **inner orbit** (WHERE / WHO / WHEN / WHY / WHAT) stays the
  same — five foundations, one identity core.
- The **outer orbit** is now five products, not three:
  - **FlowDesk** — the AI trading cockpit (HOW · INCUBATED)
  - **CCBus** — the Web3 toolkit (HOW · INCUBATED)
  - **CatoBigato** — the AI tutor (HOW · INCUBATED)
  - **WhereQ Cloud** — the data platform (HOW · PLATFORM, new)
  - **WhereQ.cc** — the private gallery (HOW · INCUBATED, graduated)

Two of those new connections matter most:

1. **WhereQ Cloud → WHO (KeyToMarvel).** A data platform is only as
   good as the identity it can attach to a record. Cloud is now the
   first product that trusts the identity core by default — every
   pipeline job tags its outputs with the user that owns them.

2. **FlowDesk → Cloud.** FlowDesk used to call free-tier providers
   directly, one request at a time. Now it reads from the shared
   schema that Cloud maintains. Cloud's collection schedule becomes
   FlowDesk's source of truth; FlowDesk becomes a thin presentational
   layer over Cloud's data.

That's the same pattern the other products follow, and it's the one
that lets the universe scale without every product re-implementing
auth, schemas and refresh jobs.

## Per-planet changes

### WhereQ Cloud (new)

The first **platform** in the outer orbit — not a product on its
own, but the layer every product sits on top of.

- Owns the shared PostgreSQL schema (one schema, one source of truth)
- Runs every scheduled collection job (market data, feeds, metrics)
- Pulls from free-tier providers where a paid integration isn't worth
  the cost yet
- Exposes collection monitoring — every job has a status, every
  record has a freshness timestamp

See the deep-dive section on the `/` page for the full planet panel.

### WhereQ.cc (graduated)

The fourth product to graduate from incubation. It started as a
side-project photo tool, became a friction-free local-first vault,
and is now a real planet in the universe.

- Local-first vault: originals stay encrypted in the user's browser
- In-browser encryption: nothing leaves the device without the user
  explicitly choosing to share
- On-demand AI enhancement: ask for "make it warmer" or "describe
  this" and the AI runs against the local copy
- Albums and sharing: standard photo-app ergonomics, minus the cloud
  lock-in

The graduation announcement is in the Incubation section on `/`.

## Operational changes

This release also makes a few non-user-visible changes that the
maintainer should know about:

- `vite.config.ts` and `vercel.json` are unchanged — the COOP/COEP
  contract from `v1.0.0` is preserved exactly. If you're reading
  the deploy runbook for the first time, that's the load-bearing
  invariant in §19.
- The bundle size warning is unchanged from the previous release;
  we don't code-split the heavy multimedia deps on purpose.
- No new environment variables. `VITE_GA4_MEASUREMENT_ID` remains
  the only runtime config; set it in Vercel → Settings →
  Environment Variables to enable analytics.
